Snippet of the week

Declarative HTTP clients with @HttpExchange

Write an interface, and Spring generates the HTTP client for you. It runs on RestClient, so it works in any Spring Boot 3.2+ or 4.x app.

UserClient.java + ClientConfig.java
@HttpExchange("/users")
public interface UserClient {

  @GetExchange("/{id}")
  UserDto getById(@PathVariable Long id);

  @PostExchange
  UserDto create(@RequestBody CreateUserRequest body);
}

@Configuration
class ClientConfig {

  @Bean
  UserClient userClient(RestClient.Builder builder) {
    RestClient rest = builder
        .baseUrl("https://api.example.com")
        .build();
    return HttpServiceProxyFactory
        .builderFor(RestClientAdapter.create(rest))
        .build()
        .createClient(UserClient.class);
  }
}

// Usage: just inject it
UserDto u = userClient.getById(42L);
Explain like I'm 5

Imagine a menu at a restaurant. You point at "pizza" and a pizza comes. You never walk into the kitchen.

The interface is your menu. Each method is one dish: "get user 42". Spring is the waiter who carries your order to the other server and brings the answer back as a UserDto.

You write the menu. Spring does all the walking.

Why it matters

Less code to test, one place for base URL and headers, and the client reads like documentation of the remote API.

New Java feature · JDK 27 · JEP 531 · Third preview

Lazy Constants: final fields that initialise on first use

A LazyConstant computes its value the first time you call get(), then never again. The JVM treats the result like a real constant, so it can be optimised as well as a static final field. It replaces the double-checked locking and holder-class tricks people write for lazy singletons.

PricingService.java · javac/java --enable-preview --release 27
// Before: thread-safe lazy init, the hard way
private volatile ExchangeRates rates;
ExchangeRates rates() {
  ExchangeRates r = rates;
  if (r == null) {
    synchronized (this) {
      r = rates;
      if (r == null) rates = r = loadRates();
    }
  }
  return r;
}

// After: JDK 27 preview
private final LazyConstant<ExchangeRates> rates =
    LazyConstant.of(() -> loadRates());

BigDecimal toBdt(BigDecimal usd) {
  return usd.multiply(rates.get().usdToBdt());
}
Explain like I'm 5

A lunch box with a lid. Nobody packs it until the first time someone opens it. Then it's packed once, and everyone who opens it after gets the same lunch.

Use it for

Loggers, config loaded from disk, expensive clients or lookup tables that slow down startup.

Status

Preview only. It was called Stable Values in JDK 25 and renamed in JDK 26, and a fourth preview is already drafted, so the API can still change. Try it in side projects, not in production.

@Component
class OrderTools {

  private final OrderRepository orders; // your existing MongoDB repository
  OrderTools(OrderRepository orders) { this.orders = orders; }

  @Tool(description = "Find an order by its public order number")
  OrderDto findOrder(@ToolParam(description = "e.g. ORD-10293") String number) {
    return orders.findByNumber(number).map(OrderDto::from).orElse(null);

}

// The model decides when to call findOrder; Spring AI runs the round-trip

    .tools(orderTools)
    .call()
    .content();

What people are doing

Learning path · one topic per level

Basic → Advanced

Records as DTOs

Replace Lombok-heavy DTO classes with record UserDto(Long id, String name) {}. Jackson maps records out of the box, and they are immutable by default.

Sealed types + pattern switch

Model results as sealed interface Result permits Ok, Err, then switch over them. The compiler tells you when you miss a case. Final since Java 21.

Structured Concurrency

Now in its 7th preview in JDK 27. Treat a group of subtasks as one unit: if one fails, the others are cancelled. Read about it, but keep it out of production until it is final.

Intermediate · PaymentResult.java (Java 21+)
sealed interface PaymentResult permits Paid, Declined, Pending {}
record Paid(String txId)          implements PaymentResult {}
record Declined(String reason)    implements PaymentResult {}
record Pending(Instant retryAt)   implements PaymentResult {}

String message(PaymentResult r) {
  return switch (r) {
    case Paid(var tx)         -> "Paid: " + tx;
    case Declined(var why)    -> "Declined: " + why;
    case Pending(var at)      -> "Retry at " + at;
  }; // no default needed: the compiler knows every case
}
Must-have this week

Tips & tricks

  1. T1

    Turn on virtual threads with one line

    spring.threads.virtual.enabled=true makes Tomcat, @Async and scheduling use virtual threads. Great for I/O-heavy APIs. Since JDK 24, synchronized blocks no longer pin the carrier thread, so the old warning is mostly gone.

  2. T2

    Keep the JVM alive when only virtual threads run

    Virtual threads are daemon threads. For a scheduler-only app, add spring.main.keep-alive=true or the process can exit right after startup.

  3. T3

    Free memory by upgrading to JDK 27

    Compact object headers are now on by default. JetBrains' September roundup reports 10–20% less heap and 5–10% more throughput on typical workloads. Measure on your own service before and after.

  4. T4

    Lazy database connections (Boot 4.1)

    spring.datasource.connection-fetch=lazy delays taking a physical connection until the first SQL runs. Useful when a @Transactional method often returns early from cache.

  5. T5

    Traces now follow @Async (Boot 4.1)

    Micrometer context now propagates into async methods automatically. You can delete any custom TaskDecorator you wrote only to copy the trace ID.

Industry & interview questions

Interview Q&A

BasicWhat is the difference between @Component and @Bean?

@Component goes on a class you own, and component scanning picks it up. @Bean goes on a method inside a @Configuration class and returns an object you build yourself. Use @Bean for third-party classes you cannot annotate, or when construction needs logic.

MidWhy does @Transactional sometimes do nothing?

Spring applies it through a proxy. If a method in the same class calls another @Transactional method with this.save(), the call skips the proxy and no transaction starts. Other traps: the method is private, or the exception is checked (only unchecked exceptions roll back by default).

Fix: move the method to another bean, or use rollbackFor = Exception.class for checked exceptions.

MidWhen should you not use virtual threads?

For CPU-bound work, since they add no extra CPU. Also when you rely on a small fixed pool as a throttle: with virtual threads you can suddenly open 10,000 database calls at once. Limit concurrency with a Semaphore or a right-sized connection pool instead.

SeniorWhat changed in Spring Boot 4 that affects a migration from 3.x?

Boot 4 sits on Spring Framework 7 and Jakarta EE 11, keeps Java 17 as the baseline, adds JSpecify null-safety annotations across the portfolio, and splits auto-configuration into smaller modules. Plan for dependency renames, a Jackson 3 upgrade, and removal of APIs deprecated in 3.x.

Java · Week 1Easy

Is this string a palindrome?

  • Write boolean isPalindrome(String s).
  • Ignore case, spaces and punctuation. Only letters and digits count.
  • Don't use StringBuilder.reverse(). Aim for O(1) extra space.
Expected
isPalindrome("A man, a plan, a canal: Panama") // true
isPalindrome("race a car")                     // false
isPalindrome("")                               // true
Show solution
Palindrome.java
public static boolean isPalindrome(String s) {
  int i = 0, j = s.length() - 1;
  while (i < j) {
    char a = s.charAt(i), b = s.charAt(j);
    if (!Character.isLetterOrDigit(a)) { i++; continue; }
    if (!Character.isLetterOrDigit(b)) { j--; continue; }
    if (Character.toLowerCase(a) != Character.toLowerCase(b)) {
      return false;
    }
    i++;
    j--;
  }
  return true;
}

How it works. Two pointers start at each end and walk inward. Skip anything that isn't a letter or digit, compare the rest in lower case, and stop at the first mismatch.

Time O(n)Space O(1)

Follow-up they'll ask. Why not new StringBuilder(clean).reverse().equals(clean)? It works, but it builds two extra strings (O(n) memory). Also say what you'd do with null: throw, or return false, and agree it with the interviewer.

Spring Boot · Week 1Easy

Fix the endpoint that never returns 404

  • What does GET /api/users/unknown-id return with this code?
  • Change it to return 404 when the user doesn't exist.
  • Don't return the MongoDB document directly.
UserController.java (buggy)
@RestController
@RequestMapping("/api/users")
class UserController {
  private final UserRepository repo;
  UserController(UserRepository repo) { this.repo = repo; }

  @GetMapping("/{id}")
  User getUser(@PathVariable String id) {
    return repo.findById(id).orElse(null);
  }
}
Show solution

Answer. It returns 200 OK with an empty body. Returning null from a controller method is not an error to Spring, so the client can't tell "not found" from "found".

UserController.java (fixed)
record UserResponse(String id, String name, String email) {
  static UserResponse from(User u) {
    return new UserResponse(u.getId(), u.getName(), u.getEmail());
  }
}

@GetMapping("/{id}")
ResponseEntity<UserResponse> getUser(@PathVariable String id) {
  return repo.findById(id)
      .map(UserResponse::from)
      .map(ResponseEntity::ok)
      .orElse(ResponseEntity.notFound().build());
}

Why the record. The DTO controls exactly which fields leave the API, so adding a passwordHash field to the document later can't leak it.

Alternative. .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "User not found")). With spring.mvc.problemdetails.enabled=true the client gets a standard RFC 9457 error body.

Follow-up they'll ask. Where would you handle this for every controller at once? In one @RestControllerAdvice that maps a custom UserNotFoundException to 404. That's Week 3.

Best practices · Industry practices

Do this, avoid that

Do

  • Bind config to a record: @ConfigurationProperties("app.mail") record MailProps(String host, int port).
  • Use constructor injection only. It makes beans immutable and easy to unit-test.
  • Return DTOs from controllers, never JPA entities or MongoDB documents.
  • Add a MongoDB index for every field you filter or sort on in production queries.
  • Keep Actuator health and info public, everything else behind auth.

Avoid

  • Field injection with @Autowired on private fields.
  • Catching Exception in every controller. Use one @RestControllerAdvice.
  • Calling external APIs inside a DB transaction. It holds the connection while you wait.
  • Running preview features (Structured Concurrency, Lazy Constants) in production.
  • Staying on Boot 3.5 without paid support: it no longer gets free security fixes.

Real problem, solved with data

"Our API times out at lunch hour"

Problem. A Spring Boot API has a HikariCP pool of 10 connections. Each request opens a @Transactional method, calls a 300 ms external pricing API, then writes to the database. At peak, requests wait for a free connection and time out.

Diagnosis. Each request holds a connection for the whole 340 ms, but only uses it for about 40 ms of SQL. The connection is idle 88% of the time it is held.

Hold time · before
340 ms
Hold time · after
40 ms
Max req/s · before
~29
Max req/s · after
~250

Fix. Call the pricing API before the transaction starts, and keep only the write inside @Transactional. Max throughput ≈ pool size ÷ hold time = 10 ÷ 0.04 s = 250 req/s, up from 10 ÷ 0.34 s ≈ 29 req/s. Boot 4.1's lazy connection fetch helps too, when the code path cannot be split.

Illustrative numbers for a worked example. Measure your own with hikaricp.connections.usage in Actuator metrics.
