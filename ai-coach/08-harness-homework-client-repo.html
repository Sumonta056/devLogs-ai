Harness Homework

By the end of this homework, your client project has a working Claude Code harness. It is committed to the repo and merged through a reviewed PR, so everyone on the project gets the same setup.

Goal and rules

Deliverable: one PR on an ai-harness branch (or any branch name that fits your convention) that contains: a lean CLAUDE.md, at least one .claude/rules/ file, safety hooks, shared permission rules, one skill, one subagent, one MCP server (or a documented CLI), and an updated .gitignore.

Rules of the road

  • It's a client repo. Never commit secrets, credentials, tokens or client data. This applies to CLAUDE.md, rules, skills, agent briefs, hook scripts and .mcp.json alike.
  • Check before you commit AI config to the client repo. Confirm with your tech lead (and the client, if your contract requires it) that .claude/ and CLAUDE.md may live in their repo.
  • One shared setup, not personal ones. Team facts go in committed files. Personal taste goes in CLAUDE.local.md, .claude/settings.local.json or ~/.claude/ (optional).
  • Depth before breadth. One of each, actually used, beats five of each never used. Don't create extra skills yet. Keep them minimal: at least one that you will use often in your project.

Step 0Prepare

Step 1CLAUDE.md, the project constitution

Aim for a project CLAUDE.md of under 30 lines: commands, facts the agent gets wrong, and pointers to detail.

Target shape:

# <client-project>: <stack>
## Commands
- tests: <cmd>   lint: <cmd>   run: <cmd>
## Facts the agent gets wrong (keep current)
- <fact 1, with the file that is the source of truth>
- <fact 2>
## Detail (loaded when relevant)
- API conventions: `.claude/rules/api.md` (path-scoped; loads by itself)

Step 2.claude/rules/ for detail

Rules hold detail that is too long or too specific for CLAUDE.md. Add a paths field and a rule only loads when Claude reads a matching file.

---
paths:
  - "src/api/**/*.ts"
---
# API rules
- Validate every request body with the shared schemas
- Errors use { "error": { "code", "message" } }

Step 3Safety hooks (do these before anything convenient)

CLAUDE.md is advice; a hook is enforced. If a violation would page someone or block a merge, use a hook.

{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [{ "type": "command",
          "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/block-destructive.sh" }] }
    ],
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [{ "type": "command",
          "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/format.sh" }] }
    ]
  }
}

Step 4Permission rules and modes

Shared allow / ask / deny rules in .claude/settings.json give everyone the same guardrails in every mode.

Step 5One skill for a real recurring procedure

Write one skill: the procedure you'll actually use next sprint. Facts go in CLAUDE.md; procedures go in skills.

---
name: add-endpoint
description: Adds a new API endpoint with validation, error format and tests
  following this repo's conventions. Use when asked to create or scaffold an
  endpoint or route.
---
1. Read .claude/rules/api.md
2. ...

Step 6One subagent with a scoped job

A subagent is a contractor in another building. It never sees your chat, so it gets only what's in its file and in the brief you hand it.

---
name: test-runner
description: Runs the test suite or a subset and reports only failures with
  file:line. Use when tests need running or CI is red. Does not fix failures.
tools: Bash, Read, Grep
model: haiku
maxTurns: 15
---

Step 7Connect one external tool (MCP or CLI)

Connect one tool you'll use this sprint. Always prefer a CLI over an MCP server if a good CLI exists. Every connected MCP server costs context in every session, whether you use it or not.

Step 8Skill packs, plugins and one spec-driven featureOptional

Do this only after Steps 1–7 are done and working.

Step 9Verify and open the PR

The harness is code: it goes through a PR and the team reviews it like any other change.

Expected layout after merge:

<client-repo>/
├── CLAUDE.md                # lean, < 30 lines
├── .mcp.json                # one server, no secrets
├── .gitignore               # + CLAUDE.local.md, .claude/settings.local.json
└── .claude/
    ├── settings.json        # hooks + permission rules (+ enabledPlugins)
    ├── hooks/               # block-destructive.sh, format.sh
    ├── rules/               # api.md (paths-scoped) ...
    ├── skills/<name>/SKILL.md
    └── agents/<name>.md
