Move 1 · Entry point
Find the entry point first
Before reading any logic, find where a request enters the system. Every other file hangs off that one line.
NewsletterController.java
@PostMapping("/api/newsletter/subscribe") public ResponseEntity<SubscribeResponse> subscribe(     @Valid @RequestBody SubscribeRequest req) {   return service.subscribe(req.email()); }
Ask the agent: “Which function runs first when a reader clicks Subscribe? Give the file and line.”
Backend
@PostMapping, @GetMapping, route config
Frontend
the page in pages/ and its @click
Jobs and events
@Scheduled, listeners, main()

Move 2 · Tests
Read the happy-path test before the code
A test is the shortest true story of what the code should do. Read the success case first, edge cases later.
NewsletterControllerTest.java
@Test void subscribe_newEmail_returns201() {   mvc.perform(post("/api/newsletter/subscribe")       .content("{\"email\":\"ola@x.no\"}"))     .andExpect(status().isCreated());   assertThat(repo.existsByEmail("ola@x.no")).isTrue(); }
Given
a new email: ola@x.no
When
POST /api/newsletter/subscribe
Then
201 Created, and saved once
Tip: read test names as a spec. A missing test name is a missing behaviour.

AI Coaching · Shape · 09
Move 6 · Summary
Write one sentence in your own words
If you can't summarize the change in one sentence, you haven't understood it yet. The agent's description doesn't count.
Copied from the PR description
“Implements robust, scalable newsletter subscription functionality with proper validation and error handling.”
Says nothing you can check.
Your sentence
“POST /subscribe trims and lowercases the email, saves it once and sends one welcome mail. A repeat email gets 200, not an error.”
Every claim can be checked.
The test: could a teammate review the PR from your sentence alone?

Step 1 · Loops & goals
Give the agent a goal and a loop
Don't approve every edit. Say what done means, how to check it, and when to stop. Then let it iterate.
Goal
Write code
Run checks
All green?
no · try again
Report
Stop limit: 5 tries, then report
prompt
Goal:  all tests in NewsletterControllerTest        pass. Loop:  run ./mvnw test -Dtest=Newsletter*,        fix the code, run again. Stop:  all green, or 5 tries → report. Never: edit or delete a test to pass.

Step 2 · Acceptance criteria
Turn acceptance criteria into tests first
Each criterion becomes a failing test before any code exists. Then 'done' is checked by a machine, not by you watching.

AI Coaching · Acceptance criteria · 15
Step 3 · Complete snapshot
Ask for one complete snapshot at the end
Don't watch the agent work. Ask it to hand back everything you need to judge the result, in one place.
SNAPSHOT.md
Diff summary
Files changed, and why, in plain words
Test output
The full run: passed, failed, skipped
Screenshots
Desktop, tablet and phone after the change
Open risks
What it couldn't check, and what it guessed
Prompt
“When you're done, write SNAPSHOT.md with a diff summary, the full test output, screenshots and open risks. Don't stop before it exists.”
Result: you review once, at the end, with evidence in hand.

Step 6 · Checkpoints
Set checkpoints so you can always go back
Long autonomous runs need save points. Commit at every green step, and rewind a bad turn instead of untangling it.
CP1
Tests written
commit · tests red
CP2
API green
commit · 3 of 3 pass
CP3
UI done
commit · form works
CP4
Devices checked
commit · screenshots
CP5
PR ready
SNAPSHOT.md
Bad turn: agent rewrote the service
/rewind to CP2
terminal
git commit -m "checkpoint: API green"   # a save point you own
