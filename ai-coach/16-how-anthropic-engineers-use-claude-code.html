How Anthropic engineers use Claude Code
Ask for results, not tasks: Felix Rieseberg's four dimensions, with right and wrong prompts, the full flow and the checkpoints.
AI Coaching · Anthropic's playbook · 01
The problem
Claude delivers exactly what you ask for
The output is correct and still feels incomplete. The limit is how we hand work over, not the tool.
Task executor
You hand over a task. Claude does the minimum that marks it done, because the prompt never says what done is for.
Results-driven collaborator
You hand over the outcome. Claude works out the sub-tasks itself and keeps going until the result holds.
Why it works: goal-setting research shows people given specific, hard goals outperform people told to just finish the task. Agents respond the same way.
AI Coaching · Anthropic's playbook · 02
The framework
Four ways to go beyond what's needed
Most teams stop at speed. The other three change what the work becomes.
01
Speed
The same work, done faster. Where most AI users already are.
02
Altitude
Work at a higher level of abstraction: hand over the result, let Claude find the steps.
03
Depth
Work like the best expert in the field: real tools, real data, proof.
04
Range
Look at the work through fields nobody would normally invite in.
Rule of thumb: speed makes you quicker; altitude, depth and range make the result better.
AI Coaching · Anthropic's playbook · 03
Altitude
Prompt
02 · Altitude
Hand over the result, not the ticket
Wrong
Task prompt
Fix bug ticket #142: null pointer in ArticleService.
You get: One ticket closed. The next crash is already in the queue.
Right
Result prompt
Make the app crash-free. Find every crash path, fix the root causes, and show me the crash rate before and after.
You get: Claude finds the sub-tasks, groups root causes and proves the result.
Fits: any job with a clear outcome. It is weaker for creative work, where there is no single best result.
AI Coaching · Anthropic's playbook · 04
Altitude
Prompt
02 · Altitude
Say what the dashboard is for
Wrong
Task prompt
Build a dashboard that shows our hiring numbers.
You get: Charts of raw counts. Nobody knows what to do next.
Right
Result prompt
We want to hire faster. Build the hiring dashboard around that: where we miss targets and why, the decisions due this week, and a fix for each.
You get: A decision tool, not a chart wall.
Test: if the prompt would still make sense with the goal removed, it is a task prompt.
AI Coaching · Anthropic's playbook · 05
Depth
Prompt
03 · Depth
Ask for the expert's method, not their tone
Wrong
Role prompt
You are a senior performance engineer. Make the site faster.
You get: The same approach, written more confidently. Small tweaks.
Right
Method prompt
Make the article page feel like it loads instantly. Start from a production trace and the bundle report, fix the critical path, prove each change with before and after numbers.
You get: A re-architecture backed by evidence.
Unreasonable goals: “instantly” forces a rethink of the system; “faster” invites a minor tweak.
AI Coaching · Anthropic's playbook · 06
Depth
Habit
03 · Depth
Every deep prompt names three things
Felix keeps a meta-prompt that rewrites a plain request into a deeper one. Each rewrite adds the same three parts.
Tools
Which expert tools to use: profiler, tracer, load test, query planner.
Starting materials
Real inputs to start from: traces, logs, the bundle report, production data.
Proof
How the result is checked: numbers, a passing test, a reproduced and fixed bug.
Try it: ask Claude to rewrite your next prompt so it names tools, starting materials and proof, then run the rewrite.
AI Coaching · Anthropic's playbook · 07
Depth
Habit
03 · Depth
Never let the builder grade its own work
Review goes to an outside judge: a fresh, non-interactive Claude Code session or another CLI such as Codex.
terminal
claude -p "Review the changes on this
branch against docs/spec.md.
List every gap as file:line.
Do not edit any files."
Fresh context
The judge never saw the build session, so it has no reason to defend it.
Read-only
It reports findings; the builder fixes them.
Spec as the bar
It checks against the written goal, not the diff's own story.
Loop
Fix, then run the judge again until it comes back clean.
AI Coaching · Anthropic's playbook · 08
Range
Prompt
04 · Range
Describe what the app does for people
Swap nouns for verbs. The verb tells you which fields should look at the work.
Wrong
Noun
Build a job board for our clients.
You get: A job board. Only an engineer's view of it.
Right
Verb
Build a tool that helps job applicants and client companies trust each other.
You get: New lenses: trust and safety, hiring psychology, marketplace design.
AI Coaching · Anthropic's playbook · 09
Range
Sub-agents
04 · Range
Run specialist sub-agents in sequence
Each sub-agent reviews and changes the app from its own field, then passes the codebase on.
Trust and safety
Fake listings, abuse, verification.
Hiring psychology
What makes an applicant apply and stay.
Accessibility
Every flow by keyboard and screen reader.
Outside judge
Checks the result against the goal.
Prompt: “Spawn sub-agents for trust and safety, hiring psychology and accessibility. Run them one after another; each changes the app from its field, then hands it on.”
AI Coaching · Anthropic's playbook · 10
Setup
Habit
Environment
Big goals need a place to verify progress
Telemetry and tools
Connect monitoring, such as crash reporting through MCP, so Claude reads real failures.
Matching context
The code version that matches the running app, so findings line up with the source.
Execution sandbox
A place to reproduce the bug, test the fix and measure performance on its own.
Wrong
Goal only
Make it crash-free. (No crash data, no way to run it.)
You get: Guesses dressed up as fixes.
Right
Goal + setup
Make it crash-free. Crash reports via MCP, staging sandbox, current release tag.
You get: Fixes Claude has reproduced and verified.
AI Coaching · Anthropic's playbook · 11
Workflow
Habit
The flow
One loop from goal to verified result
1
State the result
The outcome and why it matters, not the ticket.
2
Wire the setup
Telemetry, matching context, a sandbox.
3
Name the method
Expert tools, starting materials, proof, an unreasonable bar.
4
Run a range pass
Specialist sub-agents in sequence.
5
Call the judge
A fresh headless session audits the work.
Judge finds gaps
Back to step 3 with the findings as the new starting material.
Judge comes back clean
Ship it with the evidence attached.
AI Coaching · Anthropic's playbook · 12
Workflow
Checklist
Checkpoints
Nine checks before, during and after a run
Before you press enter
The prompt names an outcome, not a ticket.
The bar is measurable, or deliberately unreasonable.
Claude can reach telemetry, real data and a sandbox.
While Claude works
Its plan names expert tools and starting materials.
It reproduces a problem before fixing it.
Fields beyond engineering reviewed the work, where range matters.
Before you merge
A fresh session or another CLI judged the work.
Every claim comes with before and after evidence.
Findings are fixed and the judge re-ran clean.
