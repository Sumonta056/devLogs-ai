  Step 2
  
Profile where the time goes, then check the config

  
EXPLAIN is a plan. Profiling shows what actually happened: was the time spent reading data (I/O) or sorting and building temp tables (CPU and memory)? That answer changes the fix.


SET profiling = 1;
-- run the slow query
SELECT ...;
SHOW PROFILES;
SHOW PROFILE FOR QUERY 1;

  
On newer MySQL versions, performance_schema and EXPLAIN ANALYZE give the same insight; SHOW PROFILE is deprecated but still common in interviews.

  Step 3
  
Why ten joins get slow: the nested loop

  
InnoDB joins with a nested loop by default. For every row of the first (driving) table, it looks up matches in the next table, then the next. Cost grows roughly as driving rows × lookups per joined table.

  Step 4
  
Let the smallest result set drive the join

  
The optimizer usually picks the order, but statistics can mislead it. When you know better, STRAIGHT_JOIN forces tables to be read in the order you write them.
