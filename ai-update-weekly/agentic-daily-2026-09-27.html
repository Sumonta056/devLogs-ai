Official · anthropics/skills (example-skills plugin)

A skill that tests local web apps by having Claude write Python Playwright scripts. It bundles a with_server.py helper that starts your servers, waits until they're ready, then runs the script.

Agent Rule of the day

Investigate before answering

Official · Claude prompting best practices (link is the German-locale page; snippet is English)

A drop-in instruction block that stops the agent from making claims about files it hasn't opened. It targets a very common failure: confidently describing or "fixing" code it never read.

  • Prevents hallucinated method names, fields and config keys.
  • Forces a Read before any claim, especially when you name a file.
  • Short enough to paste straight into CLAUDE.md or AGENTS.md.
Paste into CLAUDE.md
<investigate_before_answering>
Never speculate about code you have not opened. If the user references a specific file,
you MUST read the file before answering. Make sure to investigate and read relevant
files BEFORE answering questions about the codebase. Never make any claims about code
before investigating unless you are certain of the correct answer - give grounded and
hallucination-free answers.
</investigate_before_answering>

For your stack: most valuable with Spring auto-configuration and Nuxt auto-imports, where behavior lives in files the agent tends not to open.

Claude Resource of the day

Effective context engineering for AI agents

Official · Anthropic Engineering · 29 Sep 2025

Anthropic's essay on treating context as a limited budget to curate, not just a prompt to write. It covers what good context looks like, just-in-time retrieval and techniques for long tasks.

  • Explains "context rot" and aims for "the smallest possible set of high-signal tokens".
  • Load data just in time through file paths, queries and links instead of stuffing it in up front.
  • Three long-task techniques: compaction, structured notes and sub-agents, the ideas behind /compact, CLAUDE.md and subagents.
Try it · 15 min
1. Read "Context Engineering for Long-Horizon Tasks".
2. Open your CLAUDE.md and delete anything Claude
   could find with a quick grep.
3. Replace pasted docs with pointers, e.g.
   "API contract: see backend/src/main/resources/openapi.yaml"

Quote: "Every new token introduced depletes this budget by some amount, increasing the need to carefully curate the tokens available to the LLM."

MCP Server of the day

MongoDB MCP Server

Official (MongoDB) · ~1.1k stars (repo page, 27 Sep) · v3.0.4

MongoDB's own MCP server connecting Claude to databases and Atlas clusters. Tools cover queries, aggregations, indexes and collections, plus Atlas admin.

  • Claude can check real collection schemas while writing Spring Data repositories.
  • --readOnly doesn't register create, update or delete tools at all.
  • --indexCheck rejects queries that would scan a whole collection.
Try it · command adapted, not run
claude mcp add mongodb \
  --env MDB_MCP_CONNECTION_STRING="mongodb://localhost:27017/myDatabase" \
  -- npx -y mongodb-mcp-server@latest --readOnly --indexCheck
claude mcp list    # expect: Connected

Security: keep --readOnly on and point it at local or dev databases only. Pass credentials as env vars, not arguments. The env value is saved in ~/.claude.json, so use a dev-only credential. Destructive tools ask for confirmation by default. The command is assembled from the README's JSON config plus Claude Code MCP syntax; there's also an official plugin: claude plugin install mongodb@claude-plugins-official.

Hook of the day

Re-inject context after compaction

Official · Claude Code hooks guide · SessionStart + matcher "compact"

A SessionStart hook that runs after every compaction. Whatever the command prints to stdout is added to Claude's context, restoring rules the summary may have dropped.

  • Fixes the mid-session drift where Claude "forgets" conventions after auto-compaction.
  • Deterministic: the reminder is always injected.
  • Swap the echo for a dynamic command like git log --oneline -5, as the docs suggest.
.claude/settings.json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "compact",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'Reminder: backend is Spring Boot (./mvnw test before commit); frontend is Nuxt 3 (npm run lint). Recent work:'; git log --oneline -5"
          }
        ]
      }
    ]
  }
}

For your stack: the structure is from the docs; the echo text is tailored. For context you want at every session start, the docs recommend CLAUDE.md instead.

Command of the day

/btw side questions

Official · Claude Code interactive mode docs

Ask a quick question about the current work without adding it to conversation history. Claude answers from what's already in context and shows the answer in a dismissible overlay.

  • Works while Claude is still running, without interrupting the turn.
  • Keeps "what was that again?" out of your context; cheap while the cache is warm.
  • Press f to fork it into a background subagent when you need tools. No tool access otherwise.
Try it
/btw what was the name of that config file again?
/btw which repository class did you say handles the Mongo pagination?

Note: the first line is the docs example, the second is an adaptation. The VS Code panel needs extension v2.1.227+.

Prompt pattern of the day

Explain why a rule exists

Official · prompting best practices, "Add context to improve performance"

Instead of a bare command, state the reason behind the rule. Claude then applies it more reliably and extends it sensibly to cases the rule didn't spell out.

  • Bare rules get applied too literally or ignored at the edges.
  • The reason covers related cases without writing a separate rule for each.
  • CLAUDE.md is easier to maintain when the purpose sits next to the rule.
Before → after
# official example
Before: NEVER use ellipses
After:  Your response will be read aloud by a text-to-speech engine, so never
        use ellipses since the text-to-speech engine will not know how to
        pronounce them.

# adapted for Spring + Mongo
Before: Never call MongoTemplate directly in controllers.
After:  Controllers must not call MongoTemplate directly, because all Mongo
        access goes through services that apply tenant filtering and
        @Transactional boundaries; skipping them leaks cross-tenant data.

How others are using it

5 real workflows

A Claude Code template for Spring Boot

Spring BootPiotr Minkowski24 Mar 2026
  • CLAUDE.md in six parts: plan mode for 3+ step tasks, a self-improvement loop that logs corrections in tasks/lessons.md, "verification before done", and rules for when to use skills and agents.
  • .claude/skills/ holds java-architect, spring-boot-engineer, jpa-patterns, api-contract-review and more; .claude/agents/ holds 8 roles including code-reviewer and test-automator.
  • Requires positive and negative tests for all generated code and uses /agents, /skills and /cost to see what's loaded.

Which extension layer? A decision guide

Updated 25 SepHidekazu Konishi
  • Six questions pick the layer: deterministic → hooks/permissions; external system → MCP; every session → CLAUDE.md or path rules; on-demand procedure → skill; isolation → subagent; cross-repo → plugin.
  • Load timing: CLAUDE.md and MCP tool names are always in context; skill bodies and MCP schemas load on demand; hooks and subagents run outside the main context.
  • Main anti-pattern: enforcing guarantees with prose. "never edit .env" in CLAUDE.md is a request; a PreToolUse deny is a guarantee.

Enforcing TDD with hooks and the red-green loop

TDDThe Prompt Shelf5 Apr 2026
  • Prompt-only TDD fails because instructions drift after compaction.
  • A PreToolUse tdd_guard.py on Write/Edit exits 2 when no matching test file exists; a PostToolUse script runs tests and feeds output back.
  • Limit: it checks that a test exists, not that it's good, so review still matters.

Parallel agents: a safe eight-phase workflow

ParallelismAakash Ahuja16 May 2026
  • Plan, scaffold shared contracts, split by ownership, dispatch to worktrees, test, merge in dependency order, validate, clean up.
  • Agents own non-overlapping directories; only one touches lockfiles, migrations or contracts.
  • Worktrees stop file collisions but not contract drift. Your job becomes managing branches.

Why you don't need the Nuxt MCP with Claude Code

NuxtAlexander Opalic31 Dec 2025
  • MCP costs context through large tool definitions and redundant intermediate results.
  • Instead, a "Nuxt Content Specialist" subagent fetches content.nuxt.com/llms.txt, picks relevant pages and reads them in its own context.
  • The author claims about 98% fewer tokens (his figure, not verified).

Suggestions for your stack

Nuxt · Spring Boot · MongoDB

Add a lessons loop

Borrow Minkowski's tasks/lessons.md: every time you correct Claude on a Spring or Nuxt convention, it appends the lesson, and CLAUDE.md tells it to read that file first. Then run /doctor prompt-audit to trim rules written for older models.

Move guarantees into hooks

Deny edits to .env and application-prod.yml with a PreToolUse hook, add a Stop hook that won't finish until the affected module's tests pass, and add today's SessionStart "compact" hook so conventions survive compaction.

TDD guard on both stacks

Adapt tdd_guard.py so editing src/main/java/**/X.java requires XTest.java, and editing a component or composable requires a matching *.spec.ts. Pair it with ./mvnw -q test -Dtest=XTest or npx vitest run <file>.

MongoDB MCP, read-only, dev only

Use the MongoDB MCP server with --readOnly --indexCheck against a local database to check schemas and indexes while writing repositories. Keep Testcontainers for tests, not the MCP server.

Nuxt docs via llms.txt, not MCP

Create .claude/agents/nuxt-docs.md, a research subagent that reads Nuxt's llms.txt and returns only what's relevant. Pair it with the spring-boot-engineer agent for backend work, each in its own worktree with its own ports.

Official Claude resources

Anthropic docs and engineering blog

How we built Claude Code auto mode

Engineering blog25 Mar 2026
  • Two layers: a prompt-injection check on incoming content, and a classifier that reviews each action before it runs.
  • A fast yes/no check runs first, with fuller reasoning only when needed. False positives drop from 8.5% to 0.4%.
  • Honest about limits: it still misses about 17% of truly risky actions, and a blocked agent is steered to a safer approach.

Harness design for long-running application development

Engineering blog24 Mar 2026
  • Separate planner, generator and evaluator agents, because agents grading their own work praise mediocre results.
  • Turns subjective frontend quality into concrete grading criteria: design, originality, craft, functionality.
  • "Every component in a harness encodes an assumption about what the model can't do", so revisit scaffolding with each new model.

Scaling Managed Agents: decoupling the brain from the hands

Engineering blog8 Apr 2026
  • Separates the "brain" (Claude plus harness) from the "hands" (sandboxes and tools), so each can fail or be swapped independently.
  • About 60% faster median time-to-first-token, over 90% faster at p95.
  • The session log lives outside the context window, so the harness pulls slices of past events on demand.

How we contain Claude across products

Engineering blog25 May 2026
  • Three overlapping layers: environment (sandboxes, VMs), model (classifiers, prompts) and filtering outside content.
  • Throwaway containers for claude.ai, sandboxing with a human in the loop for Claude Code, full VMs for Cowork.
  • The worst failures came from Anthropic's own custom code, such as a proxy leaking data through approved domains.
