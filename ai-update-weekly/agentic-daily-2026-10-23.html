Key learnings today

Read these first
01

Pin your SDKs before you upgrade

API version 2026-10-21 shipped with new major SDKs (Java 3.0.0, TS 1.0.0). They change the auth header, the license and request rules all at once. Pin versions in Maven and npm now, then migrate on a branch.

02

Temperature is gone, so get consistency elsewhere

The new API version rejects temperature, top_p and top_k, even at their default values. Get consistent output from structured outputs and validation, such as a Spring DTO with Bean Validation.

03

Skills are now a cross-tool standard

Anthropic gave Agent Skills to the Linux Foundation's AAIF, which already looks after MCP. A SKILL.md you write for your stack should also work in Copilot and Cursor, so keep team skills in the repo.

04

Fold subagents before adding more

Anthropic's new guidance: one agent loop that loads skills when needed often beats a set of specialist subagents. Keep a subagent only when an eval shows it helps.

Official (MongoDB) · 184 stars (repo page, 23 Oct) · Apache-2.0

MongoDB's own skill pack for coding agents. This skill covers data-modelling patterns and anti-patterns. Its SKILL.md is a short index ("3 anti-pattern rules, 4 fundamentals, 11 design patterns") pointing to reference files that Claude loads only when it needs them.

Agent Rule of the day

Keep modified files and test commands through compaction

Official · Claude Code best practices, "Manage context aggressively"

A one-line CLAUDE.md rule that tells compaction what it must keep. Without it, after an auto-compact the agent can forget which files it changed and how to check them, then edit them again or say it's done without running the tests.

  • The docs suggest it "to ensure critical context survives summarization".
  • It passes the docs' own pruning test: "Would removing this cause Claude to make mistakes?"
  • Pairs with /compact <instructions> when you compact by hand.
Paste into CLAUDE.md · first line copied
# Workflow
- When compacting, always preserve the full list of modified files and any test commands
  - backend: the exact ./mvnw -Dtest=... test invocations used
  - frontend: the exact npx vitest run <file> commands used

For your stack: in a mixed Nuxt + Spring Boot repo, a compacted session often forgets which side it changed. The two sub-lines are our adaptation, not the docs' text.

MCP Server of the day

Playwright MCP

Official (Microsoft) · ~38.0k stars (repo page, 23 Oct) · Node.js 18+

Browser automation for Claude through Playwright. It works from structured accessibility snapshots instead of screenshots, so it doesn't need a vision model.

  • Predictable page interaction ("Avoids ambiguity common with screenshot-based approaches").
  • Good for exploratory UI checks where the browser should keep its state between steps.
  • The README itself recommends the Playwright CLI + skills for high-throughput coding agents, because it uses fewer tokens.
Try it
# copied from README
claude mcp add playwright npx @playwright/mcp@latest

# adapted: in-memory profile, headless
claude mcp add playwright -- npx @playwright/mcp@latest --isolated --headless

Security: "Playwright MCP is not a security boundary." By default the browser profile is saved to disk, so logged-in cookies persist; --isolated keeps it in memory. --allowed-origins doesn't affect redirects, and you should treat page content as untrusted input. For your stack: point it at the Nuxt dev server, have Claude click through a form and check the calls to Spring, then turn the steps into a real @playwright/test spec.

Hook of the day

Auto-format after every edit

Official · Claude Code hooks guide, "Auto-format code after edits" · PostToolUse + matcher "Edit|Write"

After each file edit, jq pulls out the edited path and Prettier formats that one file. Formatting no longer depends on Claude remembering to do it.

  • Hooks give "deterministic control: certain actions always happen rather than relying on the LLM to choose to run them".
  • Silent when it succeeds and costs no context.
  • No more whitespace and quote-style noise in diffs.
.claude/settings.json · copied (needs jq)
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"
          }
        ]
      }
    ]
  }
}

For your stack: Prettier formats .vue, .ts and .css as they are. For Java, a second handler running ./mvnw -q spotless:apply works but formats the whole project, so it's slow (our suggestion, untested). The if field (e.g. "if": "Edit(*.ts)") limits which edits run the hook.

Command of the day

! shell mode

Official · Claude Code interactive mode, "Shell mode with ! prefix"

Start your input with ! to run a shell command yourself, without Claude choosing or approving it. The command and its output go into the conversation, and Claude responds to the output by default.

  • "run ! npm test and get an explanation of the failures without a second prompt".
  • Ctrl+B sends a long command to the background, and Tab autocompletes from earlier ! commands.
  • Set respondToBashCommands: false if you want the output added to context without a reply.
Usage example · first two from docs
! git status
! npm test
! ./mvnw -q -Dtest=OrderServiceTest test     # adapted
! npx nuxi typecheck                          # adapted

Caveat (docs): unless the session uses strict sandbox mode, ! commands run outside the sandbox, because the sandbox only applies to commands Claude runs.

Prompt pattern of the day

Symptom + location + what "fixed" looks like

Official · Claude Code best practices, "Provide specific context in your prompts"

Instead of naming a bug, give three things: what you see, where it probably is, and a definition of done Claude can check, ideally a failing test first. It combines the docs' "Describe the symptom" advice with "Give Claude a way to verify its work".

  • Narrows the search, so Claude reads fewer files.
  • A failing test gives a clear pass/fail, so Claude can keep working on its own.
  • Prevents patching the symptom: "address the root cause, don't suppress the error".
Before → after

After:  users report that login fails after session timeout. check the auth

        that reproduces the issue, then fix it

        it and show the test output.

What's trending

8 items · 18 – 23 Oct

API version 2026-10-21 and new major SDKs (Java 3.0.0, TS 1.0.0)

APIOfficialPlatform release notes21 Oct 2026
  • What: the first new API version since 2023-06-01. temperature/top_p/top_k return 400 even at their default values, and so do document blocks in assistant messages. The new SDKs (Python 2.0.0, TS 1.0.0, Java 3.0.0, Go 2.0.0 and others) send it by default. Whatever API version you use, the new SDKs send the key as Authorization: Bearer instead of X-Api-Key, Text Completions is removed, and the license moves from MIT to Apache 2.0.
  • Why it matters: a dependency bump can break builds and requests, and any gateway or Spring filter that reads X-Api-Key stops seeing the key. 2023-06-01 still works with no announced end date (per enjoy.dev).
  • Do: pin the Java SDK in your pom and the TS SDK in package.json. Search your code for temperature/topP, then migrate on a branch with /claude-api api-version (Claude Code 2.1.307).

Claude Code 2.1.303–2.1.309: /auto-mode-setup, workspace trust for ultrareview, rm denial

ReleaseOfficialClaude Code changelog18–22 Oct 2026
  • What: 2.1.304 adds /auto-mode-setup and fixes --worktree deleting branches without asking. 2.1.305 adds sandbox.allowNestedUserNamespaces, which the changelog warns can bypass the sandbox's file protections. 2.1.307 adds /claude-api api-version, a claude_code.safety_event OTel event and @claude review stop. 2.1.309: claude ultrareview requires workspace trust, and in bypass mode on Desktop and VS Code rm/rmdir is denied immediately.
  • Why it matters: most of these changes tighten safety, and auto mode now has a guided setup.
  • Do: run /auto-mode-setup on your monorepo, add --trust-workspace to CI scripts that call ultrareview, and leave nested namespaces off unless you have a real need, such as Testcontainers inside the sandbox.

Kevin Welter · subagents

General AI suggestions

Keep one plan or spec document in the repo that records why each decision was made, and have a different model review the main model's work.

"You need to know why you made a decision," and "you can't automate a process that does not exist." Debated: the episode itself says this can be overkill for a small team, and Mollick (below) says prompting matters less.Latent Space podcast · Tenex · 21 Oct

Measure whether AI spend pays off (e.g. PR throughput before and after) and watch PR size, because AI-assisted PRs are getting bigger.

Suggestions for your stack

Nuxt · Spring Boot · MongoDB

Pin, then migrate to API 2026-10-21

Pin com.anthropic and @anthropic-ai/sdk at their current majors. On a branch, remove temperature/topP, check any filter or gateway that reads X-Api-Key, and run /claude-api api-version. Move output checks to DTOs with Bean Validation.

One instruction file, rules split by path

Keep a short root CLAUDE.md or AGENTS.md with build commands, layout and the definition of done. Put Nuxt rules in a file scoped to frontend/** and Spring rules in one scoped to backend/**/*.java, and add today's compaction rule.

Install skill packs, then trim them

Add mongodb/agent-skills for schema reviews and try rrezartprebreza/spring-boot-skills (Boot 3/4; it targets JPA, so you may need a small Spring Data MongoDB skill of your own). Then run /skill-doctor and turn off the skills that never fire.

TDD against real dependencies

Have Claude write a failing test first. Use Testcontainers with @ServiceConnection for MongoDB and test slices (@DataMongoTest, @WebMvcTest) to keep runs fast. Add Galarza's idea of a verification script that starts Spring and the Nuxt dev server so the agent can check its change end to end.

Parallel worktrees that don't collide

Run one frontend and one backend agent in separate worktrees, each with its own server.port, Nuxt port and Mongo database name (set through .worktreeinclude and an env file). Deny writes outside the repo, as issue #103805 shows why.
