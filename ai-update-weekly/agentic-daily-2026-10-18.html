Key learnings today

Read these first
01

Make guardrail hooks fail closed

Claude Code 2.1.294–2.1.300 fixed hooks that didn't block, added onFailure: "block" and now validates updatedInput. Add the flag to safety hooks and re-test any hook that rewrites commands.

02

Haiku 5.5 is a subagent model, so route by size

Overriding Explore with Haiku cut one tester's read-only cost from $0.62 to $0.016 a question. A wide fan-out cost more, and community posts warn about a 100K-token price step, so keep Haiku tasks small and pin effort.

03

Trace agents like any other service

The Platform now exports OpenTelemetry spans (beta, 14 Oct, Java SDK included), and Claude Code adds GenAI span attributes. Send them to the same backend as your Spring traces.

04

MCP servers are stateless now

MCP spec 2026-07-28 removes the initialize handshake and session IDs. Pass explicit handles such as a Mongo cursorId as tool arguments so servers scale behind a load balancer.

Agent Rule of the day

Run single tests, not the whole suite

Official · Claude Code best practices, "Write an effective CLAUDE.md"

A line from the docs' example CLAUDE.md that stops the agent re-running the full suite after every small change. The same page gives a test for every rule: "Would removing this cause Claude to make mistakes?" If not, cut it.

  • Agents love looping mvn test or the full Vitest suite, which wastes minutes and fills context with logs.
  • Pairs with the doc's companion line: "Be sure to typecheck when you're done making a series of code changes".
  • The doc also warns "If you emphasize many lines, none of them stands out", so save IMPORTANT for one rule.
Paste into CLAUDE.md · first line copied
# Workflow
- Prefer running single tests, and not the whole test suite, for performance
  - Backend: ./mvnw test -Dtest=OrderServiceTest#createsOrder
  - Frontend: npx vitest run path/to/Component.spec.ts

For your stack: Spring context startup makes full runs slow, so this saves the most time on the Java side. The two sub-lines are our adaptation.

Claude Repository of the day

anthropics/claude-code-action

Official · ~8.9k stars (repo page, 18 Oct)

"A general-purpose GitHub action, built on Claude Code, that answers questions and implements code changes on PRs and issues." It starts on an @claude mention, an issue assignment or an automation prompt, and works with the Anthropic API, Bedrock, Vertex AI and Foundry.

  • Claude Code in PR threads and issues, with no local session needed.
  • claude_args takes --allowedTools, --max-turns and --system-prompt, so you can fence it in CI.

.github/workflows/claude.yml · adapted from examples/claude.yml
name: Claude Code
on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]
jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write
      actions: read # Required for Claude to read CI results on PRs
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          claude_args: |
            --max-turns 10
            --allowedTools "Bash(./mvnw -q test*),Bash(npm run lint:*)"

MCP Server of the day

MongoDB MCP Server

Official (MongoDB) · ~1.1k stars (repo page, 18 Oct)

An MCP server that lets Claude query and manage MongoDB and Atlas. Tools include find, aggregate, explain, collection-schema, collection-indexes and create-index, plus Atlas admin tools.

  • Claude checks real schemas and indexes before writing Spring Data queries instead of guessing field names.
  • explain confirms an index is actually used.
  • --indexCheck "enforces that query operations must use an index, rejecting queries that perform a collection scan."
Try it · adapted from README + MCP docs
claude mcp add --env MDB_MCP_CONNECTION_STRING="mongodb://localhost:27017/myDatabase" \
  --transport stdio mongodb -- npx -y mongodb-mcp-server@latest --readOnly --indexCheck

Security: --readOnly "only allows read, connect, and metadata operation types". Destructive tools and $out/$merge ask for confirmation. Keep the prompt-injection warning on (don't pass --disableUntrustedDataWarning), pass credentials by env var, use a least-privilege user, and don't put a real password in a project-scoped .mcp.json. For your stack: "inspect collection-schema for orders, write the @Query, verify it with explain."

Hook of the day

Stop guard: don't finish while tests fail

Community · Odilon Hugonnot (dev.to) · Stop behaviour confirmed in the hooks reference

A Stop hook that runs your tests when Claude tries to end its turn. If they fail it exits 2, which "Prevents Claude from stopping, continues the conversation", and it checks stop_hook_active so it blocks only once.

  • A deterministic gate: no more "done!" while the build is red.
  • The anti-loop check stops it from blocking forever.
  • Stop has no matcher, so the settings block is short.
.claude/hooks/stop-guard.sh + settings.json · adapted
#!/bin/bash
# stop-guard.sh  (chmod +x, needs jq)
input=$(cat)
if [ "$(echo "$input" | jq -r '.stop_hook_active')" = "true" ]; then
  exit 0
fi
if ! ./mvnw -q test > /tmp/stop-guard.log 2>&1; then
  echo "Tests are failing. Fix them before finishing:" >&2
  tail -n 30 /tmp/stop-guard.log >&2
  exit 2
fi
exit 0

# .claude/settings.json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          { "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/stop-guard.sh" }
        ]
      }
    ]
  }
}

For your stack: the original runs Go tests; we swapped in ./mvnw. Use npx vitest run for Nuxt, or -pl api to scope a slow suite. On 2.1.295+, consider onFailure: "block" too.

Prompt pattern of the day

Let Claude interview you

Official · Claude Code best practices, "Let Claude interview you"

For bigger features, start with a short prompt and have Claude interview you with the AskUserQuestion tool, then write a spec. Implement it in a fresh session.

  • Surfaces edge cases and tradeoffs before any code is written.
  • The written spec gives the implementation session a clean context.
  • Good specs "name the files and interfaces involved, state what is out of scope, and end with an end-to-end verification step".
Before → after · template copied
Before: Add order cancellation to the app.

After:  I want to build order cancellation (Nuxt UI + Spring Boot API + MongoDB
        status history). Interview me in detail using the AskUserQuestion tool.

        Ask about technical implementation, UI/UX, edge cases, concerns, and
        tradeoffs. Don't ask obvious questions, dig into the hard parts I might
        not have considered.

        Keep interviewing until we've covered everything, then write a complete
        spec to SPEC.md.

# then: /clear  →  "implement SPEC.md"

For your stack: expect questions on refund state, concurrent updates to the same order, and embedded vs separate status-history collection.

How the Claude Code team does code review

Anthropic staffOsmani, Lunt & Wang · claude.dev15 Oct 2026
  • Code owners write a REVIEW.md next to a short CLAUDE.md: what failure looks like in that area, a cap on nits, paths to skip, file:line evidence required, and a summary that opens with a count.
  • /code-review and /security-review run locally before a PR; parallel reviewer agents plus a voting step keep only agreed findings, tagged Important, Nit or Pre-existing.
  • Risk tiers: Low needs no human once checks are green, Medium 1, High 2; agent approvals never count, and reviews stop after 3 rounds. Reported: one-round pass rate rose from 65% to 78%.

Idle compaction: what it does and how to turn it off

ContextDevelopers Digest17 Oct 2026
  • Since 2.1.299, a 200K+ session idle for ~54 minutes compacts before the 1-hour cache expires (the 54 minutes comes from a commenter's binary analysis).
  • Turn off with "idleCompaction": false in settings.json or /config (2.1.302+); raise CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS to delay it.
  • Disable it for fragile sessions (half-done plans, orchestrators) and keep durable instructions in CLAUDE.md so no summary can drop them.

General AI suggestions

Enforce conventions with a pre-commit hook that fails the commit and tells the agent what to do, not only with an AGENTS.md line.

Prompts drift; a deterministic check doesn't. Huntley reports compliance went to "ten out of ten". Debated: his "delete your AGENTS.md every couple of months" clashes with earlier advice to keep one.Geoffrey Huntley · ghuntley.com · 13 Oct

Paste the docs URL of the library or API into the task.

The agent works from current docs instead of stale training data; a linked vendor eval reports completion going from 41% to 84% (unverified).Ben Tossell · Ben's Bites · 15 Oct

Compare models by tokens per finished task, not price per token.

Run today's MongoDB MCP pick with --readOnly (or MDB_MCP_READ_ONLY=true), a least-privilege DB user and --indexCheck. MongoDB also announced a hosted Atlas Managed MCP Server that names Claude Code as supported.

A REVIEW.md per layer

One for the Nuxt app/ code (failure = hydration mismatches, SSR data leaks) and one for Spring services (failure = unscoped Mongo queries, missing validation). Cap nits, require file:line evidence, and run /code-review before each PR.

Haiku for search, Opus for edits

Override Explore with model: haiku, effort: medium for read-only digging through Vue components and Spring packages, and use --max-budget-usd on headless test generation. Keep fan-out small; the parent's reading cost can eat the savings.

A real test gate per stack

Use PostToolUse hooks only to show results (./mvnw -q test for backend paths, Vitest for frontend — our split). Make the blocking gate today's Stop guard or a pre-commit hook with onFailure: "block", and keep RED→GREEN rules in CLAUDE.md.

What's new in Claude Haiku 5.5

Docs7 Oct 2026
  • 1M context and 128k output (Haiku 4.5: 200k/64k); adaptive thinking on by default, controlled through effort.
  • Responses can start with thinking blocks, so pick content by type, not position; it can return stop_reason: "refusal".
  • About 30% more tokens than Haiku 4.5 for the same text, which matters when estimating cost.

Prompting Claude Haiku 5.5

Docs7 Oct 2026
  • medium is the default effort; at low it's more likely to skip searches, stop early or skip checks.
  • With JSON output and thinking off it may skip tool calls; fix with adaptive thinking, tool_choice, or "JSON applies to the final answer only."
  • For coding agents, require a real check (tests, type-checker or build), and if none can run, have it say which one it skipped and why.

OpenTelemetry export

DocsBeta · 14 Oct 2026
  • Spans for Messages and Sessions API calls, token usage, Managed Agents turns and tool calls, using GenAI semantic conventions.
  • Set up via SDK tracing, a Console destination (Admin needed), or both. Default sends metadata only; "Full content" adds prompts and responses (0.75 MB per span cap).
  • Delivery is best effort; the Usage API stays the authoritative record.

Browser and computer use with the SDK

DocsBeta · 7 Oct 2026
  • New BetaAbstractBrowserToolset20260801 and BetaAbstractComputerToolset20260801 classes: the SDK runs the loop, you supply the browser or desktop.
  • Use partner drivers (Browser Use, Browserbase, Daytona, E2B) or your own, e.g. Playwright, via client.beta.messages.tool_runner(tools=[...]).
  • No URL checks unless you write a policy; javascript_exec and file_upload need a confirm callback.
