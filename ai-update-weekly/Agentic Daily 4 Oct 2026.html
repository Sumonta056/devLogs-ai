A model upgrade is more than changing the ID

Sonnet 5.5 (28 Sep) is faster and cheaper, but forced tool_choice now returns a 400 error and "thinking disabled" changed. Run your real tasks on both models before you switch the default.

02

Permission rules are now your main safety control

Claude Code 2.1.284 starts sessions in auto mode, Mods can change runtime behaviour, and 2.1.289 had to fix deny rules that leaked through symlinks. Write explicit deny rules and upgrade.

03

Treat MCP servers like npm dependencies

Agent Rule of the day

Don't hard-code to pass tests

Official · Claude prompting best practices, "Avoid focusing on passing tests and hardcoding"

A rule that stops the classic "make the test green" shortcut, where the agent special-cases test inputs or weakens assertions. It also tells the agent to report a wrong test instead of working around it.

  • Prevents hard-coded return values and special cases written just to match test fixtures.
  • Makes clear that tests check the solution; they don't define it.
  • One paste into CLAUDE.md or AGENTS.md.
Paste into CLAUDE.md
Please write a high-quality, general-purpose solution using the standard tools
available. Do not create helper scripts or workarounds to accomplish the task more
efficiently. Implement a solution that works correctly for all valid inputs, not
just the test cases. Do not hard-code values or create solutions that only work
for specific test inputs. Instead, implement the actual logic that solves the
problem generally.

Focus on understanding the problem requirements and implementing the correct
algorithm. Tests are there to verify correctness, not to define the solution.
Provide a principled implementation that follows best practices and software
design principles.

If the task is unreasonable or infeasible, or if any of the tests are incorrect,
please inform me rather than working around them. The solution should be robust,
maintainable, and extendable.

For your stack: most useful on JUnit/Spring Boot suites and Vitest specs, where agents like to tweak assertions until they pass.

Hook of the day

Block edits to protected files

Official · Claude Code hooks guide · PreToolUse + matcher "Edit|Write"

A PreToolUse hook that runs a script before every file edit. If the path matches a protected pattern, the script exits with code 2 and its "Blocked:" message goes back to Claude, which then tries a different approach.

  • Deterministic: .env and lockfiles can't be edited even if Claude ignores a CLAUDE.md rule.
  • Claude is told why the edit was blocked, so it doesn't just fail silently.
  • Easy to extend with more patterns.
.claude/hooks/protect-files.sh + settings.json
#!/bin/bash
# protect-files.sh  (chmod +x)
INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
FILE_PATH="${FILE_PATH//\\//}"
PROTECTED_PATTERNS=(".env" "package-lock.json" ".git/")
for pattern in "${PROTECTED_PATTERNS[@]}"; do
  if [[ "$FILE_PATH" == *"$pattern"* ]]; then
    echo "Blocked: $FILE_PATH matches protected pattern '$pattern'" >&2
    exit 2
  fi
done
exit 0

# .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.sh" }
        ]
      }
    ]
  }
}

For your stack (adapted): add application-prod.yml, pnpm-lock.yaml and src/main/resources/db/migration/ to the patterns.

Command of the day

/rewind (or Esc Esc)

Official · Claude Code checkpointing docs

"Run /rewind, or press Esc twice when the prompt input is empty, to open the rewind menu." Pick any earlier prompt, then restore code, the conversation, both, or summarize from or up to that point.

  • A fast undo when the agent goes off track, without juggling git.
  • "Summarize from here" frees the context used by a long debugging detour but keeps your original instructions.
  • Checkpoints are saved with the session, so it still works after /resume.
Usage example
/rewind
# → pick the prompt before the composable refactor
# → "Restore code"

/rewind
# → pick the message where the Spring debugging detour began
# → "Summarize from here"

Limits: it doesn't track files changed by Bash (rm, mv, generated migrations), it usually doesn't restore subagent edits, and it skips hard-linked files like pnpm's. The docs say it's "Not a replacement for version control."

Prompt pattern of the day

Say what to do, not what to avoid

Official · prompting best practices, "Control the format of responses"

Describe the output you want instead of listing what's forbidden. A clear target gives the model something to aim at, while a ban only rules one thing out.

  • Reduces vague results and overcorrection.
  • Makes CLAUDE.md rules shorter and easier to check.
  • Works well alongside the "explain why a rule exists" pattern from 27 Sep.
Before → after
# official example
Before: Do not use markdown in your response
After:  Your response should be composed of smoothly flowing prose paragraphs.

# adapted for Nuxt
Before: Don't use the Options API.
After:  Write components with <script setup lang="ts"> and the Composition API.

Claude Sonnet 5.5 launches as the new default mid-tier model

ReleaseOfficialAnthropic28 Sep 2026
  • What: claude-sonnet-5-5 costs $2/$10 per million input/output tokens and $0.20 per million cache reads, the same as Sonnet 5. APIOfficialClaude Platform release notes28 & 30 Sep 2026
  • What: On Sonnet 5.5, forced tool_choice (any/tool) returns 400. To turn thinking off at high effort or below, use thinking: {"type": "between_tools"}. Sonnet 5.5's safety fallback to Sonnet 5 draws criticism

SecurityThe New Stack · MIXED28 Sep – 1 Oct 2026
  • What: Classifiers send higher-risk cyber work and some frontier-LLM requests to Sonnet 5, and the conversation stays there. They check everything the model reads, including search results and files. On the API, fallback is opt-in; without it, flagged requests simply end.
  • Why it matters: An agent reading untrusted pages or repos can be silently switched to another model or stopped partway through a run. The New Stack cites tests where 12.01% of rerouted requests were compromised by prompt injection.
  • Do: Log the model that served each response, decide whether to enable fallback, and handle refusals explicitly. A HN thread exists, but we couldn't load it to check its contents.

General AI suggestions

Before an agent deploys anything, put hard budget caps on every cloud service it touches: the service stops, not just an email alert.

Agents make it easy to ship things that cost money, and a runaway service can quietly cost thousands overnight.Simon Willison · simonwillison.net · 3 Oct

Split agent work into short, focused sessions and steer with engineering terms like "tracer bullets" (one end-to-end path first).

Agents build layer by layer, which causes bugs where the layers meet; short contexts keep each session sharp. Debated: Mollick (below) argues detailed structure matters less now.Pragmatic Engineer with Matt Pocock · 17 Sep

Sort AI-written PRs by risk: send API, auth and schema changes to humans, and spend human time on plans and tests rather than every line.

Suggestions for your stack

Nuxt · Spring Boot · MongoDB

Audit before the 5.5 model switch

Run today's grep for tool_choice, temperature and "disabled" across your Spring AI config and Nuxt server routes. Replace forced tool calls with structured outputs, then compare Sonnet 5.5 and Opus 5.5 on cost per task.

Run tests after every Spring edit

Copy the springbokdev pattern: a PostToolUse hook on Write|Edit that runs ./mvnw -q test. On larger projects, narrowing it to the affected module with -Dtest=… is our suggestion, not the starter's.

Path-scoped rules on both ends

Add .claude/rules/domain-rules.md (no Spring or Mongo annotations in domain classes) and persistence-rules.md (@Document and repositories stay in adapters). Add a Nuxt rules file written as positive instructions, following today's prompt pattern, and install the antfu nuxt skill.

Tighten permissions for auto mode

Allow Bash(./mvnw test:*), Bash(pnpm test:*) and Bash(pnpm nuxi typecheck:*). Set ask on anything that writes data or deploys, deny Read(./.env) and Read(**/application-prod.yml), add the protect-files hook, and upgrade to 2.1.289.

Let Claude see the browser

Add Chrome DevTools MCP with --no-usage-statistics and a dev Chrome profile, and ask Claude to check Nuxt hydration warnings and failing useFetch calls to Spring before it says it's done. Pair it with the vue-expert subagent.

Coding sessions use more context. Opus 5.5 is built for that

Claude blog24 Sep 2026
  • About 40% cheaper to run than Opus 5, with the biggest savings in long, context-heavy sessions.
  • Recent Claude Code changes cut cache misses by over 50%: changing effort and forking subagents no longer invalidate the cache.

Test plugins with evals (claude plugin eval)

Docsv2.1.269+Week 37 digest
  • Each case is evals/<case>/prompt.md plus graders (regex, tool-was-called, or a rubric scored by a model). claude plugin eval init drafts a suite for you.
  • Each case runs 3 times with the plugin and 3 times without; the report shows the score difference and an estimated cost.
  • --threshold makes CI fail when the score drops below a set level, so you can test a skill before you share it with the team.

Compaction on demand

DocsBeta compact-2026-09-04
  • Send compaction={"type":"summarize"} to get stop_reason:"compaction" and a signed block to put first in later requests.
  • Your code decides when to compact, instead of an automatic token threshold. Built for long agent loops.
  • Can't be combined with context_management, stop sequences, structured output or forced tool_choice.
